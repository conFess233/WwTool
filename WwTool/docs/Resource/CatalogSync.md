# 游戏资料同步

资料位于 `Local/Data`，分为 `Characters.json`、`Weapons.json`、`Albums.json`、`Motors.json`。四个文件独立维护字符串版本号（例如 `"version": "3.7.0"`）和以游戏 ID 为键的 `items`。版本支持一至四段非负整数，整体须大于零；逐段按数值比较，缺少的末尾段视为零，例如 `3.10.0 > 3.7.0`、`3.7 = 3.7.0`。兼容旧正整数版本及旧同步状态中的整数版本；不要使用小数 `3.70` 代替分段版本。本版本不读取或迁移旧的 `GameItemsResources.json`；缺失或损坏时使用程序内嵌的初始配置，损坏文件先保留备份。

## 同步规则

启动后，分别检查距上次成功同步是否满 24 小时；设置页的“同步游戏资料”可立即检查全部类别。同一时间只执行一个同步任务，取消保留已经完成的类别。

仅从 GitHub 仓库 `conFess233/WwTool` 的主分支（仓库默认分支，当前为 `master`）读取四个配置文件，不再请求官方目录接口或进行官方增量补充。仓库版本较高时按 ID 合并有效字段，保留本地额外记录、未知字段和远端未提供的译名；版本相同或低于本地时保留本地配置并记录仓库检查成功。缺项不会删除本地记录。

配置和同步状态通过临时文件替换写入。各类别失败互不影响，仓库主分支检查失败、文件不存在或资料无效时保留本地数据，不推进该类别的成功时间。发布此功能时需要将四个配置文件一起合入仓库主分支；合入前保留初始配置并显示失败。旧版官方同步成功状态在启动时重置为待同步，以重新检查仓库来源。

`isLimited`、稀有度、图片地址和多语言名称由仓库配置维护，同步时不再根据官方数据推测或补充分类。缺少译名时保留旧值，显示时回退中文和调用处的名称或 ID。

所有名称均为空的未完成记录保留在原始配置中，但暂不生成展示模型；后续同步补全名称及必要字段后恢复显示，不因单条未完成记录阻断整份资料加载。

## 图片

图标按游戏 ID 使用 `Local/Icons/{ID}.png`。加载顺序为随包本地图、有效缓存、仓库默认分支的 `WwTool/Local/Icons/{ID}.png`、默认图。只有本地图和有效缓存都缺失时才按需请求仓库，不使用配置中的 `iconUrl` 获取外部图标，也不下载整个图鉴。资料与图片共用仓库默认分支查询，常规检查结果缓存 24 小时；手动同步会重新查询，清空图片缓存允许下次下载重新查询。

仓库不提供半身立绘。角色页使用最近同步的攻略站快照中的 `illustrationPictureUrl`，进入页面后在后台准备立绘和卡片所需的装备图标。悬停本身只读缓存，准备完成后刷新相关卡片；无立绘地址或下载失败时回退头像，不额外查询官方角色目录，也无需手动维护配置中的 `portraitUrl`。

图片缓存位于 `Local/Cache/Images`，不写回随包图标目录。资料同步时只检查已有缓存，使用 ETag/Last-Modified 条件请求；随包本地图仍优先使用。下载和解码成功后才替换缓存，失败保留有效旧图。图片下载最多并发 4 个，每次下载限时 10 秒，最大 20 MB。

404、网络或解码失败后，同一图片 24 小时内不自动重复请求；取消不记为失败。手动同步、清空图片缓存或重启程序可提前重试。手动同步和清空缓存也会让当前角色页重新准备缺失立绘。下载期间显示默认图或头像，成功后自动替换；失败只写日志，不逐张弹出通知。切换账号或离开页面会取消该页面的准备任务，清空缓存后未完成的旧下载不能重新写回缓存。

资料变化会通知名称绑定、角色页和抽卡统计，图片同步完成会刷新正在显示的图片。设置页显示四类资料的版本、数量、同步结果和上次成功时间。
